# Software for multi-omics data integration and analysis: a systematic and critical comparison of frameworks, packages, workflows and platforms, with EasyMultiProfiler as a featured workflow for microbiome research

## Abstract

The routine generation of genomic, transcriptomic, proteomic and metabolomic data from the same biological system has turned multi-omics integration from a methodological aspiration into a daily expectation, yet the software landscape answering this demand is fragmented across unsupervised factor-analytic engines, supervised discriminant frameworks, deep representation-learning architectures, pathway-aware aggregators, microbiome-native pipelines and graphical web platforms. This review applies a common set of criteria—input data structures, handling of missingness, supervision regime, scalability, biological target, reproducibility infrastructure and empirical benchmarking—to a curated set of frameworks, packages, workflows and platforms, organised along three axes: the stage at which integration is performed (early, intermediate or late), the degree of supervision required, and the biological question being addressed. We critically discuss general-purpose Bioconductor frameworks such as MultiAssayExperiment, mixOmics, MOFA and pathwayMultiomics; microbiome-centred tools including gNOMO, gNOMO2, PALM and EasyMultiProfiler; and point-and-click platforms such as Profiler, ExpOmics, ExpressVis, the Analyst ecosystem and MONGKIE. EasyMultiProfiler, an R workflow built on SummarizedExperiment and MultiAssayExperiment and organised into extraction, preparation, support, analysis and visualisation modules, is featured as an example of microbiome-centred workflow design that aligns host and microbial assays within standardised data structures. We argue that the field's binding constraint is no longer algorithmic novelty but the absence of shared benchmarks, ground-truth corpora and FAIR-compliant evaluation infrastructure; claims of superiority should therefore be read with caution, and progress will depend less on yet another statistical engine than on reproducible, microbiome-native assessment.

## 1. Introduction: why multi-omics integration demands dedicated software

The premise that biological systems can only be understood by simultaneously interrogating multiple molecular layers has, in little more than a decade, moved from methodological aspiration to routine expectation. A single study now routinely combines genomic, transcriptomic, proteomic and metabolomic assays, often at single-cell or spatial resolution, and with metagenomic, metatranscriptomic and metaproteomic layers when the system of interest is a microbial community [1, 2]. Each layer is generated by a different assay, preprocessed by a different toolchain and stored in a different format, with sample overlap that is rarely complete and with technical noise that is not comparable across modalities [3]. The heterogeneity is not cosmetic: it determines which statistical operations are even defined, and propagates through every downstream decision about imputation, normalisation, dimension reduction and testing. The community has produced a correspondingly heterogeneous software landscape, and the practical question for working scientists is no longer whether to integrate but which stack to adopt.

That choice has become harder because the algorithm catalogue has fragmented along several largely independent axes. Unsupervised latent-factor approaches such as Multi-Omics Factor Analysis infer shared and modality-specific variation [4], and the same conceptual core has been carried into single-cell profiling [5] and transfer-learning extensions [6], with the MOFA2 release line representing the actively maintained successor whose broader bulk/single-cell behaviour is not separately characterised in the cited evidence. Matrix-factorisation methods for incomplete multi-omics blocks have been added to the catalogue [7], while parallel network-based meta-analytic frameworks now unify statistical aggregation with similarity-network-fusion-style integration [8]. A separate longitudinal literature models repeated measurements of the same subjects [9, 10], and pathway-aware tools offer functional annotations and biological priors that can be used to improve the interpretability of integrative results [11, 12]. A parallel deep-learning literature frames integration as representation learning rather than decomposition [13, 14, 15, 16, 17], and the single-cell regime has generated its own dedicated probabilistic and graph-linked ecosystems, including scVI and its semi-supervised extension scANVI [18, 19] and totalVI for paired RNA and surface protein measurements [20]. Web-based platforms wrap subsets of these algorithms behind point-and-click interfaces [21, 22, 23, 24, 25], while reproducibly containerised pipelines package yet other subsets for command-line execution [26, 27]. Data structure convergence around MultiAssayExperiment [28] and its single-cell counterpart [29] is partial; file conventions and evaluation metrics remain heterogeneous across the tools reviewed, so applying several methods to the same dataset typically requires substantial engineering effort [30].

Microbiome research sharpens every one of these difficulties. A meaningful microbiome study must coordinate at least four interacting layers — the microbial community, its viruses, its host and the metabolic exchange between them — each profilable by multiple assays with non-overlapping sample sets. Disease-focused work in type 2 diabetes illustrates the gap: reproducible metagenomic signatures can be linked to functional pathways and metabolites, but the chain from genetic potential to expressed activity to host phenotype depends on whether metabolomic, metatranscriptomic and proteomic measurements were obtained on the same individuals [31]. Pipelines such as gNOMO and gNOMO2 address part of this problem for amplicon, metagenomic, metatranscriptomic and metaproteomic data with and without host context [27, 32], and microbiome-aware multi-omics workflows built on standardised R/Bioconductor classes align the microbial and host sides of the problem [3]. Even so, the field lacks a consensus benchmark, and the dominant reviews do not yet agree on what a successful integration should demonstrate.

A further, often underappreciated, dimension is that integration is not solely a statistical question. The reproducibility crisis in computational biology has shown that the same algorithm, executed by two groups on nominally the same data, can yield qualitatively different results, with the principal sources of divergence being software versions, parameter choices and undocumented preprocessing rather than the mathematical core of the method. FAIR-compliant packaging of multi-omics workflows as Research Object Crates [26], curated simulators such as SUMO for controlled evaluation [33], single-cell multi-omics benchmarks across 47 datasets [34] and comparative studies of 12 integration methods on joint scRNA-seq and scATAC-seq tasks [35] have emerged in response. These efforts reveal that the binding constraint on the field is engineering and infrastructure: data structures such as MultiAssayExperiment [28] and its single-cell counterpart [29], containerised workflow managers and provenance metadata determine which analyses are even tractable before statistical sophistication is brought to bear.

Existing reviews of multi-omics software tend to conflate three quite different objects — algorithms, packages and end-to-end workflows — within a single list [2]. The consequence is that a reader finishes such a review no better equipped to choose between, for instance, a deep-learning framework, a factor-analysis package and a microbiome-centred pipeline than before reading it. This review adopts a deliberately narrower ambition: it applies a common set of criteria — input data structures, handling of missingness, supervision, scalability, biological target, reproducibility infrastructure and empirical benchmarking — to a curated set of frameworks, packages, workflows and platforms, and uses those criteria to situate one microbiome-centred workflow as a featured example. The aim is not to crown a winner but to expose, through comparison, the engineering choices that quietly determine which scientific questions are answerable.

## 2. A taxonomy of integration strategies: stages, supervision and biological target

The term "multi-omics integration" is frequently invoked as though it referred to a single statistical operation, yet the algorithmic landscape encompasses fundamentally different commitments to the data-generating process. Methods as superficially similar as similarity-network fusion and matrix factorisation impose distinct assumptions about the distribution of signal across modalities, the nature of cross-platform concordance, and the role of prior biological knowledge, and a working taxonomy is required before any meaningful comparison of software tools can be undertaken. In what follows, I organise the field along three axes: the stage at which integration is performed (early, intermediate or late), the degree of supervision required (unsupervised, semi-supervised or supervised), and the biological target the analysis is designed to address (subtyping, biomarker selection, longitudinal modelling or dynamic network inference).

The most informative first axis is integration stage. Early integration concatenates normalised modality matrices into a single design matrix and applies standard multivariate or supervised methods, an approach implemented, for example, in PLS-based workflows within mixOmics [36]. Concatenation preserves the original feature space but ignores modality-specific noise structure and is highly sensitive to differences in scale and feature cardinality. Intermediate integration builds a joint latent representation, either by factor-analytic decomposition as in Multi-Omics Factor Analysis [4], MOTL [6] and Multi-Layer Matrix Factorisation [7], or by graph-based embedding as in SNF [37], MODILM [38] and MO-GCAN [16]. Late, or decision-level, integration trains separate models on each modality and combines their outputs; deep learning frameworks such as DeepMoIC [14] and MOADLN [15] instantiate intermediate integration through latent representation fusion, with downstream classification heads that yield decision-level outputs. Crucially, these three strategies are not interchangeable: the choice of stage changes the failure modes of an analysis, and tools marketed under a single integration label frequently combine stages internally without disclosing the implications.

The second axis concerns supervision. Unsupervised factor-analytic methods dominate the literature precisely because matched multi-omics cohorts are usually too small to support fully labelled learning; MOFA infers shared and modality-specific latent factors without external labels and then enables downstream subtyping, imputation and outlier detection [4], while mixOmics provides a continuum from unsupervised PLS variants to the supervised discriminant variant DIABLO [36, 39]. Semi-supervised approaches explicitly leverage small labelled subsets alongside large unlabelled ones: SSD-MO combines deep non-negative matrix factorisation with a semi-supervised objective and was shown to improve clustering F-scores on six TCGA datasets [40], although the extent to which these gains generalise beyond cancer subtyping has not been established. Fully supervised frameworks such as the network-based Bayesian method NetMIM [12] and the graph-attention-based MODILM [38] address biomarker selection and disease classification directly, but they depend on the existence of trustworthy endpoints and cannot answer exploratory questions about novel molecular strata.

The third axis, biological target, distinguishes tools whose statistical machinery is tailored to a specific scientific goal. Sample subtyping is the most heavily studied target: SNF fuses per-modality patient similarity networks and was reported to outperform single-modality analyses and several integration baselines across five cancer cohorts [37], while MLMF extends factorisation to handle partial multi-omics matrices across twelve multi-omics datasets drawn from cancer studies [7], and graph-attention and graph-convolutional approaches such as MO-GCAN [16] and DeepMoIC [14] target the same problem with neural architectures. Biomarker selection is the explicit objective of DIABLO [39] and NetMIM [12], the latter additionally accommodating block missingness through data augmentation. A more specialised target is longitudinal modelling, addressed by timeOmics [9] and PALM [41], with PALM aligning multi-omics time series before reconstructing dynamic Bayesian networks in an inflammatory bowel disease cohort [41]. Dynamic network inference proper, the reconstruction of time-resolved regulatory graphs spanning omics layers, is the central aim of netOmics [10] and PALM [41], and is statistically distinct from subtyping even though both produce graphical outputs.

This three-axis taxonomy should not, however, be read as a neutral classification. The benchmarks available do not yet justify a confident ranking across stages: the single-cell integration benchmark of Hu and colleagues reports that Seurat, MOJITOO and scAI outperform other vertical-integration methods on most of the 47 datasets evaluated [34], while a parallel benchmark of joint scRNA-seq and scATAC-seq integration finds that no single method dominates across tasks [35], and neither study examines bulk multi-omics subtyping or longitudinal targets. Conflating similarity-network fusion with matrix factorisation obscures a real methodological contrast: SNF operates by fusing per-modality sample similarity networks [37], whereas factor-analytic methods such as MOFA infer a small number of shared and modality-specific latent axes [4], and empirical benchmarks to date have not formally distinguished these alternative data-generating assumptions. What the literature does not show is that any single axis dominates the others; integrative method choice must therefore be made conditional on the assumed data-generating process, the size and labelling of the cohort, and the specific biological question being asked, and software reviews that ignore these axes risk endorsing tools whose assumptions are violated by the very data they are applied to.

## 3. General-purpose statistical and Bioconductor integration frameworks

integration frameworks occupy an unusual position in the multi-omics software landscape: they are not tied to a particular biological question or sample type, but instead supply statistical machinery that operates on whatever blocks the user supplies. Within the R/Bioconductor ecosystem, this category is anchored by the MultiAssayExperiment class, which provides a coordinated representation of diverse assays together with subsetting, reshaping and cross-assay aggregation primitives [28]. MultiAssayExperiment does not enforce any particular model: it is an interchange format on top of which methods such as MOFA, mixOmics or pathway-based routines can be plugged in, and the SingleCellMultiModal Bioconductor package redistributes curated landmark CITE-seq, 10x Multiome and related datasets as MultiAssayExperiment objects to support method development on standardised inputs [29].

The most visible statistical engines are the PLS-family methods consolidated in mixOmics, which provides sparse and discriminant variants for dimension reduction and feature selection across multiple 'omics blocks [36]. DIABLO, the supervised extension implemented within the same package, seeks correlated discriminant features across data types and has been adopted for cancer case studies integrating mRNA, miRNA, CpG, protein and metabolite matrices [39]. PLS-based methods are, by construction, linear and rely on cross-block covariance structure; in highly compositional or sparsity-dominated data, such as sparse microbiome count tables with many zeros and strong library-size effects, this construction can yield unstable loading signs and inflated cross-block correlations, so users are well advised to verify the linearity and correlation assumptions empirically before trusting cross-omics feature signatures. This limitation reflects the underlying PLS methodology rather than any specific shortcoming of the mixOmics implementation, and applies to any PLS-derived integrator rather than to mixOmics in particular.

Factor-analytic frameworks relax the assumption of correlated blocks by learning latent factors that can be shared or modality-specific. MOFA was introduced as an unsupervised probabilistic factor model for bulk multi-omics, providing sample subtyping, imputation and outlier detection [4]. The single-cell-focused MOFA+ generalised this formulation with scalable inference and flexible sparsity priors to handle multiple sample groups and modalities such as paired RNA and epigenetic profiling [5]. These models offer probabilistic grounding and factor-level interpretability, but the documented case studies are limited to specific cancer settings [4]; whether MOFA-style factor inference generalises to the zero-inflated compositional distributions typical of microbiome relative abundance matrices, or how factor interpretability behaves as the number of modalities grows beyond three, remains, to our knowledge, untested in the cited primary literature. Extensions such as MOTL have begun to address limited-sample settings by transferring factor structure from larger datasets [6], illustrating that active development of the MOFA family continues beyond the original publications and that conclusions drawn from the original MOFA and MOFA+ studies [4, 5] should not be assumed to characterise the current maintained releases.

A different axis of generality is pursued by pathway-level integration tools. The pathwayMultiomics package provides a roll-up strategy that does not require matched samples and uses a novel MiniMax statistic to prioritise dysregulated pathways across categorical, continuous or survival outcomes [11]. By aggregating features before integration, such methods trade the resolution of gene-level signals for robustness and interpretability; the available excerpt does not address how pathwayMultiomics handles the compositional structure that dominates microbiome data, where correlation networks at the pathway level can be driven by shared denominators rather than shared biology, so its applicability to compositional microbiome inputs should be regarded as untested rather than unsupported.

A fourth layer consists of wrapper pipelines that treat the proliferation of integration methods as a usability problem rather than a statistical one. moiraine automates preprocessing, input formatting, visualisation and side-by-side comparison of several integration tools on the same dataset [30], while MUUMI unifies statistical meta-analysis with network-based integration, including similarity network fusion, to identify robust molecular signatures in IPF transcriptomic and macrophage multi-omics data [8]. Neither wrapper ships with a Bayesian assessment of whether one integrated solution is genuinely better than another; they make comparison easier but do not adjudicate it. Similarly, SUMO provides controlled synthetic multi-omics data with user-defined latent structures [33], yet the absence of a broadly adopted ground-truth corpus continues to limit head-to-head evaluation of competing methods on a level methodological playing field.

Taken together, the generalist frameworks provide a coordinated data infrastructure [28, 29], two dominant inferential families with distinct theoretical foundations (PLS-based [36, 39] and Bayesian factor-analytic [4, 5]), and an emerging layer of comparison tooling and simulation infrastructure [8, 30, 33]. What the present evidence does not establish is that any of these general-purpose stacks ship, by default, with the microbiome-specific preparation logic that dedicated microbiome workflows typically require; this gap is part of the motivation behind microbiome-flavoured workflows such as EasyMultiProfiler, which build on the same MultiAssayExperiment container and provide a module-oriented R interface (extraction, preparation, support, analysis, visualisation), illustrated on human and mouse gut host–microbiome datasets [3]. The same caveat about absent head-to-head benchmarking applies symmetrically to the comparison frameworks discussed above [8, 30, 33], and to the as-yet-unstated behaviour of MOFA-family factor models on microbiome inputs [4, 5, 6].

## 4. Microbiome-centred multi-omics tools

Microbiome multi-omics occupies a distinctive niche within the broader integration landscape because the biological substrate—microbial communities sequenced at population scale—imposes constraints that generic statistical frameworks do not address. A 16S or metagenomic layer delivers a sparse count matrix whose units are operational taxonomic units, amplicon sequence variants or metagenome-assembled genomes, while downstream layers enter at incompatible resolutions—constraints that generic frameworks are not designed to handle [1]. Few of the general-purpose frameworks discussed elsewhere in this review were designed to align these inputs, which has motivated a small but coherent set of microbiome-native tools.

The earliest of these is gNOMO, a Snakemake-based pipeline that explicitly targets non-model host-associated microbiomes and integrates up to three meta-omics layers (metagenomics, metatranscriptomics and metaproteomics) together with host or environmental context, demonstrated on the cockroach Blattella germanica [32]. Its contribution was less the introduction of new statistical machinery than the recognition that reference databases for symbiont communities of non-model organisms are sparse and that integration must therefore accommodate partial annotation and host-derived contamination in the same workflow. gNOMO2, the modular successor, generalises this approach to canonical model microbiomes, handles two to four omics combinations including 16S rRNA, metagenomics, metatranscriptomics and metaproteomics, and adds differential-abundance, integration and visualisation modules benchmarked on four datasets [27]. Importantly, gNOMO2 is presented as a reproducible infrastructure layer rather than a statistical engine: it orchestrates established tools within a containerised pipeline and exposes integration-relevant outputs (matched feature tables, taxonomic roll-ups, functional projections) for downstream analysis, but it does not, by itself, propose a new integrative model.

A different design philosophy underlies PALM, a computational pipeline for longitudinal microbiome multi-omics that aligns time-resolved sequence, expression, metabolomic and host-transcriptomic data and reconstructs a unified model via dynamic Bayesian networks, with applications in inflammatory bowel disease [41]. PALM's distinguishing feature is its explicit treatment of temporal misalignment between layers: differences in sampling cadence and progression rate across omics are handled through a biologically inspired alignment step before the dynamic network is fit. PALM therefore addresses a complementary problem to static integration frameworks, focusing on dynamic regulatory inference in longitudinal cohorts rather than cross-sectional feature association.

Outside human and insect hosts, dedicated integration infrastructure is thinner. In livestock, a recent methodological review argues that identifying keystone microbial taxa in ruminant and monogastric guts requires network-level integration of genomic, metabolic and host multi-omics data, but the tools it evaluates are predominantly general-purpose network or matrix-factorisation methods applied to microbial data rather than pipelines built natively for that purpose, and performance claims rest on cross-domain extrapolation in the absence of livestock-specific benchmarks [42]. In clinical microbiome cohorts such as type 2 diabetes, integrative multi-omics has revealed consistent strain- and pathway-level signatures, yet most studies still rely on ad hoc combinations of metagenomic profiling, metatranscriptomics and metabolomics that are not packaged as reusable workflows; the bottleneck is no longer methodology but annotation, with strain-level resolution and host–microbe protein–metabolite linkage remaining difficult to standardise [31]. A parallel observation emerges from the tuberculosis metabolomics literature, where low concordance of differential metabolites across human and animal models coexists with conserved pathway-level disruption, suggesting that integration frameworks without explicit pathway-mapping primitives will under-detect biologically aligned signal [43].

Comparable gaps are evident in adjacent clinical and immunological domains where multi-omics is heavily used but infrastructure is underdeveloped. In exosomal cardiovascular biomarker discovery, reproducibility and validation gaps dominate despite an abundance of AI/ML integration methods, with ensemble classifiers reporting AUC in the 0.80–0.92 range, though external validation remains limited [44]; in reproductive immunology, integrative analyses of recurrent pregnancy loss still depend on borrowed frameworks such as WGCNA, MOFA and bespoke deep-learning classifiers rather than purpose-built tools [45]. A recent community roadmap emphasises that microbiome multi-omics is held back less by the absence of algorithms than by the lack of standardised workflows, benchmarked datasets and FAIR-compliant pipelines [1].

Within this landscape, EasyMultiProfiler is presented as an R-based multi-omics workflow for microbiome research that uses SummarizedExperiment and MultiAssayExperiment as unifying data structures and is organised around five named modules—extraction, preparation, support, analysis and visualisation—to standardise integration and improve reproducibility, as illustrated on human and mouse host–microbiome cohorts [3]. Its documented focus on the Bioconductor ecosystem and on model-organism host–microbiome pairs differentiates it from gNOMO's emphasis on non-model hosts [32], since gNOMO2 [27] generalises the approach to canonical model microbiomes, though this specialisation constrains rather than broadens its applicability. The EasyMultiProfiler description does not specify which operations are implemented within each of the five modules, nor does it document behaviour on non-model host microbiomes, on dynamic or longitudinal designs, or on integration scenarios beyond the human/mouse gut cohorts used in the original demonstration [3].

A candid assessment is warranted at the field level rather than at the level of any single tool. Microbiome-centred tools still suffer from severe annotation bottlenecks: functional inference for metagenomes and especially metatranscriptomes and metaproteomes remains database-bound, and strain-level ambiguity means that nominally identical species can encode different functions across cohorts. No microbiome-native gold-standard benchmark with known ground-truth interactions is currently available, and head-to-head statistical comparisons against MOFA, mixOmics-DIABLO, SNF or graph-neural-network alternatives are absent not only for EasyMultiProfiler [3] but for gNOMO2 [27], PALM [41] and the broader microbiome-integration class; benchmarking infrastructure that none of these tools provide remains the field's most pressing gap. Dynamic-modelling approaches such as PALM [41] address complementary problems and cannot be substituted by static-integration pipelines. Until microbiome-native evaluation infrastructure becomes available, claims of superiority among microbiome integration tools should be read with caution, and the field would benefit less from yet another statistical engine than from shared evaluation infrastructure.

## 5. Web servers and point-and-click platforms for multi-omics

Web servers and point-and-click platforms represent the most accessible tier of multi-omics software, packaging analytical workflows behind graphical interfaces that shield users from command-line installation overhead. Profiler [21] offers one of the broader analytic spans among the surveyed web platforms, providing a Streamlit-based environment that spans QC, preprocessing, statistical testing, machine and deep learning, biomarker discovery, pathway and drug-target enrichment, and survival modeling across proteomics, transcriptomics, lipidomics and other modalities, deployable as web or desktop application. ExpOmics [24] is similarly broad, offering seven applications and four toolkits with twenty-eight customizable functions for differential expression, co-expression, WGCNA, feature selection and enrichment across mRNAs, lncRNAs, miRNAs, circRNAs, piRNAs and proteins without organism restriction. ExpressVis [46] foregrounds biologist-oriented interactivity, organising differential expression, clustering, survival analysis and integration with protein–protein interaction networks and pathway maps into six modules. CFViSA [25] integrates dedicated microbiome and transcriptome pipelines alongside seventy-nine analysis tools and includes didactic features such as a demonstration course and task history interface, illustrating how accessibility and training are increasingly bundled into platform design.

A second category consists of platform "ecosystems" that distribute multi-omics functionality across interlinked but specialised web servers. The Analyst suite [23] is the paradigmatic example, combining ExpressAnalyst and MetaboAnalyst for single-omics processing of transcriptomics/proteomics and lipidomics data, OmicsNet for knowledge-driven integration through biological networks, and OmicsAnalyst for data-driven integration through joint dimensionality reduction; the protocol walks users through these stages on a human pancreatic islet and plasma cohort. MOPAW [47] targets the Cancer Genomics Cloud and exposes Multivariate Single Sample Gene Set Analysis (MOGSA) through a point-and-click interface, automating data preparation, dimensionality reduction and pathway analysis across CNA, transcriptomics, proteomics and phosphoproteomics data. The single-cell analyst [22] provides automated QC, processing, phenotype analysis and over twenty interactive visualisation tools across six single-cell omics types (scRNA-seq, scATAC-seq, scImmune profiling, scCNV, CyTOF, flow cytometry) and spatial transcriptomics, deployable both online and offline.

A third category privileges network-based visual reasoning. MONGKIE [48], an early Java-based entry, integrates network visualisation with omics data analysis tools for interactive visual mining of TCGA glioblastoma multi-omics layers. PhenoMultiOmics [49] narrows the network concept to enzymatic reactions, curating cancer-gene–protein–metabolite relationships and visualising perturbed reaction-induced multi-omics networks with biomarker discovery via differential expression and pathway enrichment. NOODAI [50] generalises the idea by constructing joint interaction networks from representative per-omics traits and applying the MONET decomposition tool to identify disease-relevant modules. These platforms trade methodological novelty for interpretability: anchoring interpretation in curated biological graphs reduces dependence on statistical sophistication but inherits the biases and incompleteness of those knowledge bases.

A fourth hybrid class fuses pre-curated public repositories with analysis modules, becoming searchable atlases with built-in statistics. SportsXbiodata [51] aggregates 2,563 public multi-omics exercise datasets and 3,600 publications, providing expression profiling, immune infiltration, phenotype-gene correlation, knowledge graph and enrichment analyses, with free access. LOSTdb [52] integrates 295 lung-cancer multi-omics datasets with curated metadata and modules for subtype annotation, cross-search and integrated analysis. These resources are valuable for re-use, but the analytical methods offered within them tend to be conservative, reflecting the need to operate on heterogeneous, partially standardised input data of variable provenance.

This proliferation of interfaces, however, should not be confused with methodological diversity. Five caveats are worth stating explicitly. (1) The word "unified" in many platform descriptions papers over the fact that the underlying logic is often concatenation of single-omics tools rather than joint modelling; Profiler [21] presents an extensive menu that nonetheless relies on modality-specific QC and analysis pathways stitched together at the user-interface level. The Analyst suite [23] is more transparent in this regard, formally distinguishing knowledge-driven network integration from data-driven dimensionality-reduction integration, yet even its data-driven arm depends on classical joint dimensionality-reduction algorithms that pre-date the current generation of variational factorisations [5], matrix factorisation with transfer learning [6], and contrastive deep methods [53]. (2) Web platforms systematically hide preprocessing choices from the user, which is helpful for novices but problematic for analysts who need to evaluate how filtering, normalisation and batch handling propagate downstream; the closed pipelines of MOPAW [47] and PhenoMultiOmics [49] offer little room to swap in alternative strategies, in contrast to containerised workflow frameworks such as the FAIR Digital Object pipeline for childhood externalising behaviour multi-omics [26], which exposes its dependencies via Nextflow with containerised software dependencies. (3) Most web platforms lag behind the algorithmic state of the art, neither implementing MOFA+-style scalable variational inference [5] nor the rapidly expanding family of graph neural network integrators such as MO-GCAN [16], MODA [17] or BioNeuralNet [13]; MOPAW [47] and the Analyst suite's data-driven arm [23] are partial exceptions, exposing MOGSA and joint dimensionality reduction respectively. (4) Network-oriented servers such as NOODAI [50] and PhenoMultiOmics [49] expose interpretable visual artefacts, but the underlying network priors and edge-weighting schemes are rarely benchmarked against each other, making it unclear whether observed modules reflect biology or curation bias. (5) The abundance of platforms can mask a shortage of cross-platform standards for input formats, metadata and reporting, so users face substantial friction when moving between resources; reproducibility infrastructure in particular varies across container formats (Docker, Singularity/Apptainer, Conda) and is rarely documented at the level of re-execution success on independent hardware. Taken together, web servers and GUI workflows play a substantial role in democratising multi-omics, but their rapid numerical growth is not, by itself, evidence of methodological progress.

## 6. Network-based and deep learning approaches

Network-based and deep learning approaches have become the most rapidly expanding family of methods for multi-omics integration because they explicitly encode relationships among features and learn joint representations end-to-end. The lineage begins with similarity network fusion, which constructs per-data-type patient similarity networks and iteratively fuses them into a single integrated graph for cancer subtyping and survival prediction across mRNA, DNA methylation and miRNA [37]. This patient-similarity paradigm inspired a wave of follow-up tools, and a recent unification of statistical meta-analysis with similarity-network-fusion-style integration has been demonstrated for IPF transcriptomic meta-analysis and THP-1 macrophage multi-omics data [8], suggesting that network thinking is no longer confined to a single method but increasingly serves as an interoperability layer across analytical pipelines. Together, these works established that pairwise similarity matrices, once fused, provide a basis for subtyping on the cancer cohorts in which they were demonstrated, and they set the conceptual template for the methods that followed.

Graph neural networks (GNNs) extend this logic by treating omics features or patients as nodes and learning low-dimensional embeddings through message passing. BioNeuralNet, an open-source modular Python framework, supports network construction, low-dimensional representation learning and diverse downstream tasks on gene, protein and metabolite graphs with interoperability with scikit-learn, PyTorch and NetworkX [13]; the ArXiv preprint of the same tool is available as [54]. Cancer-focused GNN frameworks have proliferated rapidly: DeepMoIC combines autoencoders, patient-similarity networks and deep graph convolutions, with pan-cancer subtyping reported as its principal task [14]; LAGProg augments biological networks with a conditional variational autoencoder to overcome the limited connectivity of biological networks (i.e., the limited number of neighboring genes) in prognosis prediction [55]; MO-GCAN pairs graph convolutions with attention across eight cancer types [16]; and MODA maps omics features onto a curated knowledge graph and reports advantages over seven existing integration methods on classification tasks [17]. CrossIsoFun specialises the GNN paradigm to isoform function prediction by combining GCN classifiers with a View Correlation Discovery Network to exploit isoform–isoform interactions [56]. Collectively, these architectures demonstrate the flexibility of graph-based learning but, as discussed below, almost uniformly report metrics on cancer panels drawn from TCGA and related resources, with few examples tested on non-malignant phenotypes, longitudinal sampling designs or microbiome–host systems.

A complementary thread replaces fixed graph topology with learned attention. MOADLN applies per-omics self-attention followed by a Multi-omics Correlation Discovery Network to fuse mRNA, methylation and miRNA [15]; MODILM uses Graph Attention Networks combined with MLPs and a View Correlation Discovery Network for complex disease classification [38]. These attention-based designs report improvements over simple concatenation in the input or feature space on the demonstrated benchmarks, but they inherit the same evaluation regime as the GNN family — accuracy/AUROC/F1 on cancer panels is the typical headline — and almost no assessment is provided of how attention weights map to biologically interpretable molecular events. A separate image-style branch converts omics matrices into 2-D images: a representative method embeds gene expression, methylation and copy-number alteration via UMAP, paints them as RGB channels and trains a convolutional neural network on the resulting images to predict Gleason score and tumour stage [57]. While conceptually elegant and effective on the demonstrated cohorts, this image-pipeline paradigm imposes an additional inductive bias — pixel adjacency becomes meaningful — for which there is no biological justification, and whose generalisation beyond prostate and breast cancer remains untested in the cited evidence.

A third stream couples deep architectures with contrastive or generative objectives rather than explicit attention. CAEncoder combines a Vision Transformer encoder with a CycleGAN generator in a contrastive end-to-end pipeline for cancer detection [53], exemplifying designs that align modalities through adversarial training and reconstruction rather than through attention-weighted fusion.

A fourth stream embeds prior-knowledge networks and Bayesian regularisation directly into the integration step. NetMIM uses a spike-and-slab prior over pathway structure and a data-augmentation scheme to handle block-wise missingness for biomarker selection and outcome prediction [12]; MINGLE performs sparse network estimation across omics layers followed by integrated visualisation for glioma heterogeneity [58]; and the NOODAI web server constructs joint interaction networks from representative per-omics traits and decomposes them with the MONET algorithm to surface disease-relevant modules [50]. These methods are more transparent than end-to-end deep models, but the cited evidence does not document stress tests of prior-strength choices or missing-data imputation against realistic null or confounded scenarios. In practice, the line between deep learning with a graph prior and a network-based Bayesian model is increasingly blurred, yet the evaluation standards remain strikingly similar across both.

Despite their methodological diversity, these approaches share three structural weaknesses. First, headline performance is reported almost exclusively on TCGA-derived cancer panels, leaving open whether the gains transfer to non-malignant disease, longitudinal cohorts or microbiome–host settings where sample sizes are smaller, batch effects more pronounced and confounders more pervasive. Second, interpretability is asserted rather than measured: attention weights, GNN message-passing scores and UMAP pixel coordinates are presented as explanations without systematic benchmarks against biological ground truth, perturbation data or expert clinician evaluation, and ablation studies that selectively remove supposedly important nodes are the exception rather than the rule. Third, predictive uncertainty is rarely exposed; an exception is TMODINET, which couples self-attentional and graph dynamic learning with a Dirichlet-based uncertainty head for cancer diagnosis [59], but even this framework evaluates trustworthiness only on classification accuracy and does not, in the cited abstract, document calibration drift across cohorts, behaviour under distribution shift or comparisons against Bayesian or conformal baselines. In the absence of standardised interpretability and uncertainty benchmarks, the consistently strong classification numbers produced by network and deep-learning methods should be read as evidence of architectural flexibility and capacity to fit curated cancer panels rather than as a demonstration of clinical or biological readiness — and, as observed across the integration literature more broadly, no head-to-head, multi-domain benchmark has, to our knowledge, been published against which these claims could be jointly evaluated.

## 7. Data structures, workflow systems and reproducibility

The foundations on which multi-omics analyses are assembled have matured considerably, but the literature shows that scaffolding choices remain highly heterogeneous. At the data layer, the Bioconductor `SummarizedExperiment` and `MultiAssayExperiment` classes are now widely accepted as a lingua franca for coordinated representation of assays, sample metadata and feature annotations, and they underpin the canonical `MultiAssayExperiment` software package that also distributes TCGA cancer data in this format [28]. EasyMultiProfiler (EMP) is documented as building on these classes to provide a multi-omics storage and analysis framework for microbiome research, organised into five modules (extraction, preparation, support, analysis and visualisation) and illustrated on human and mouse host–microbiome datasets [3]. Other Bioconductor tools extend the same scaffolding to specific analytical settings: `timeOmics` provides a generic framework for longitudinal multi-omics integration, distributed as a Bioconductor package [9], and `pathwayMultiomics` provides a pathway-based integrative analysis of multi-omics data that does not require matched samples, integrating per-pathway p-values via a novel MiniMax statistic [11]. The breadth of adoption is a strength, but it also means that any tool or workflow that ignores these structures risks creating downstream interoperability debt. A critical caveat is that `MultiAssayExperiment` is by design a container, not an analysis engine; it harmonises storage and subsetting, but it does not enforce methodological standards for the analytical operations applied to its contents. EMP and similar workflows therefore inherit the community's analytic ambiguity rather than resolving it.

Above the data layer, workflow managers such as Nextflow and Snakemake have become the de facto standard for stitching heterogeneous tools together. The microbiome pipeline gNOMO2 is a modular Nextflow implementation that integrates 16S rRNA amplicon, metagenomics, metatranscriptomics and metaproteomics data with new differential abundance, integration and visualisation modules [27], and its predecessor gNOMO used Snakemake to integrate up to three meta-omics levels in non-model organisms such as the cockroach Blattella germanica [32]. The Nextflow ecosystem in particular has been extended with rich provenance and FAIR packaging: a multi-omics analysis workflow for childhood externalizing behaviour was implemented as a modular Nextflow pipeline with containerised dependencies, version control and semantic metadata, packaged as a Research Object Crate and shared via WorkflowHub as a FAIR Digital Object [26]. Pipeline-wrapping packages fill the complementary niche of orchestrating integration tools themselves rather than upstream processing: the R package moiraine constructs reproducible multi-omics integration pipelines by automating preprocessing, formatting and side-by-side comparison of results from multiple integration methods applied to the same dataset [30]. Simulation engines occupy a related but distinct position: SUMO generates factor-analysis-based synthetic multi-omics datasets with user-defined latent structures, enabling reproducible testing and validation of integration methods where real benchmark datasets with known signals are scarce [33].

Reproducibility, however, is repeatedly declared solved by the next containerised workflow, yet the evidence suggests the field remains in a state of partial compliance. Containers and Nextflow profiles fix the computational environment, but studies routinely skip metadata standards for sample provenance, fail to pin versions of upstream reference databases (taxonomies, functional catalogues, gene models), and rarely record provenance for derived layers such as normalised counts, batch-corrected matrices or factor loadings. The FAIR Digital Object exemplar explicitly couples its Nextflow pipeline with version control and rich semantic metadata to address exactly these gaps [26], but the presence of a Dockerfile should not be equated with reproducibility; in practice, two researchers running the same container on different infrastructure may still obtain divergent results if reference data, random seeds, or numerical libraries are not pinned. Reproducibility should therefore be measured by re-execution success on independent infrastructure, including the recovery of identical intermediate objects and final outputs from raw data and metadata alone, rather than by the mere presence of container definitions. In our assessment, the published evidence for EMP, gNOMO2, moiraine and MUUMI does not document independent re-execution on heterogeneous hardware [3, 8, 27, 30]. MUUMI unifies statistical meta-analysis with network-based integration within a single R package framework [8]; in our view, its reproducibility properties likewise rest on the user's discipline rather than on enforced workflow contracts.

A realistic roadmap for the field must therefore move beyond containerisation as the gold standard. Future workflow systems should couple `MultiAssayExperiment`-style containers with explicit, machine-readable metadata schemas, mandatory pinning of reference database versions, automated checksum verification of intermediate derived layers, and continuous re-execution benchmarks on heterogeneous hardware. Until re-execution success becomes the published metric by which multi-omics tools are judged, including EMP, the gap between declarative reproducibility and verifiable reproducibility will persist.

## 8. Benchmarking evidence and evaluation criteria

The benchmarking literature on multi-omics integration is uneven in scale, scope and the dimensions of performance it interrogates. Recent efforts to systematize comparisons are typically bound to a narrow slice of biological application [1, 42] and few evaluation axes, and very few attempt head-to-head, multi-domain assessments that would justify generalised claims of method superiority. The absence of such benchmarks is field-wide rather than a deficiency of any single tool: each method has been benchmarked primarily against baselines chosen by its authors, and no independent, multi-tool benchmark of comparable breadth to the single-cell effort below currently exists. MOFA2, the active MOFA distribution, is not separately captured in the cited evidence, so this section discusses MOFA and MOFA+ as described in the original publications [4, 5] without adjudicating claims about newer releases.

The most systematic single-cell comparison remains the benchmark by Hu and colleagues, which evaluated 14 protein-abundance and chromatin-accessibility prediction algorithms alongside 18 multi-omics integration algorithms across 47 single-cell datasets spanning CITE-seq, scATAC-seq and multiome protocols, ranking totalVI and scArches as the leading predictors for protein abundance and identifying Seurat, MOJITOO and scAI as the strongest vertical-integration methods [34]. A complementary single-cell benchmark on joint scRNA-seq/scATAC-seq integration assessed 12 methods across three integration tasks, evaluating six aspects and offering method-selection guidelines rather than claiming universal superiority [35]. Individual method papers such as CelLink report their own comparative evaluations on joint scRNA-seq, spatial proteomics and CITE-seq data, but these are framed as supporting evidence for a new proposal rather than as impartial benchmarks [60]. The effect is that, even within the single-cell domain, there is essentially one comprehensive benchmark with broad coverage and many narrower comparisons embedded in methods papers. The dimensions interrogated are also restricted: most single-cell comparisons focus on batch-aware embedding quality, label-transfer accuracy and conservation of biological structure, while calibration of probabilistic outputs, robustness to missing modalities, and biological interpretability are not primary axes.

A parallel body of work has emerged in pan-cancer integration, where most new methods are introduced with a benchmarking section that compares the proposal against a handful of established baselines on cancer-derived cohorts. Ren et al.'s MLMF was benchmarked against state-of-the-art approaches across twelve multi-omics datasets, focusing on subtyping accuracy and clustering robustness, and was explicitly designed to handle both complete and partially observed modalities [7]. Similar patterns are visible in work introducing DeepMoIC [14], MOADLN [15], MO-GCAN [16], CAEncoder [53], LAGProg [55], MODILM [38], SSD-MO [40] and TMODINET [59], where TCGA cancers dominate the evaluation cohorts and where a small set of baselines — typically MOFA, mixOmics, SNF and a handful of deep-learning competitors — recur across studies. What such benchmarks establish is that, on bulk-cancer subtyping and survival tasks — most often BRCA, GBM, LUSC, OV, LIHC and similar — late-generation deep-learning or graph-based methods can marginally outperform classical matrix factorization, similarity-network fusion or PLS-based baselines under the chosen accuracy metric. They do not establish more substantial generality claims.

The limitations of this benchmarking culture are well known yet rarely confronted head-on. First, dependence on TCGA bulk cancer data means that almost every reported ranking is conditioned on a setting with hundreds of samples per study, complete-modality coverage, well-defined subtype labels and known batch structure; rankings obtained under these conditions are not necessarily preserved when sample sizes shrink, modalities become partially missing, the biological target is unsupervised, or the biology is non-cancer. Second, the evaluation axes are narrow: accuracy, occasionally a clustering index, sometimes survival concordance — but rarely calibration, uncertainty quantification, computational cost at scale, or stability of latent factors under resampling. The few methods that explicitly model uncertainty, such as the Dirichlet-based estimation in TMODINET [59], are evaluated in isolation rather than absorbed into dominant benchmark pipelines. Third, interpretability is almost always assessed in an ad hoc fashion, with authors selecting a small set of case-study genes or pathways, making any cross-method comparison of interpretability essentially impossible. Fourth, none of these benchmarks systematically addresses block or random missingness, which is the operational reality in longitudinal and clinical microbiome settings, even though dedicated missingness-tolerant methods such as NetMIM [12] and MLMF [7] exist. In the author's view, calibration, runtime, peak memory and thread-scaling should be added as first-class evaluation axes, since current reports rarely quantify these dimensions and the resulting "NS" cells in the matrix above reflect a field-wide documentation gap rather than a settled negative finding.

A particularly weak point is transferability of rankings to domains central to multi-omics research. Single-cell benchmarks give almost no guidance for microbiome, metagenomics–metatranscriptomics or longitudinal host–microbiome integration, where the unit of analysis is not a cell but a community, where dominant variation is ecological rather than developmental, and where batch structure is replaced by inter-individual and longitudinal heterogeneity. Conversely, microbiome-specific tools such as gNOMO2 [27] and PALM [41] are evaluated on their own curated datasets rather than within pan-cancer benchmark pipelines, so their performance relative to MOFA, mixOmics or MO-GCAN is largely unknown. Microbiome reviews explicitly note the absence of head-to-head benchmarking and call for standardized, FAIR-compliant workflows rather than competitive rankings [1]. Longitudinal multi-omics, exemplified by timeOmics [9], netOmics [10] and PALM [41], has its own evaluation conventions — clustering across time points and network-based reconstruction — that are disjoint from the TCGA cancer benchmark. Even within bulk cancer, simulation packages such as SUMO enable controlled testing of latent-structure recovery under user-defined noise and complexity [33], yet these have not been absorbed into dominant benchmarking pipelines.

The cumulative effect is that the published benchmarking evidence supports only modest, conditional conclusions. Within bulk TCGA cancer subtyping, late-generation deep and graph-based methods tend to outperform classical baselines by a few percentage points of accuracy under particular metrics, with no single method dominating across cancer types and tasks. Within single-cell multi-omics, totalVI, scArches, Seurat, MOJITOO and scAI represent credible leaders for specific tasks, but no method is uniformly best across protein prediction, chromatin prediction and vertical integration. Outside these domains — particularly microbiomes, longitudinal cohorts, clinical biomarker discovery, and studies with sparse or heterogeneous modalities — the benchmarking literature offers no defensible ranking at all. The field would benefit from community-endorsed synthetic benchmarks enabled by packages like SUMO [33] and from multi-domain evaluation suites that simultaneously probe calibration, missingness, longitudinal stability and biological interpretability, rather than continuing to overfit rankings to a small set of TCGA classification tasks. The discrepancy between this review's stated ambition to apply a common rubric to all reviewed tools and the field-wide absence of such a rubric is itself part of the evidence base this section documents.

## 9. EasyMultiProfiler: design, strengths and limitations relative to the alternatives

EasyMultiProfiler (EMP) is an R-based workflow for multi-omics integration in microbiome research, built around the SummarizedExperiment and MultiAssayExperiment classes that have become the de facto Bioconductor standard for coordinating heterogeneous assays [3, 28]. Its documented architecture spans five interconnected modules — data extraction, preparation, support, analysis and visualisation — and is illustrated on human and mouse gut microbiome cohorts with matched host multi-omics data [3]. By committing to MultiAssayExperiment as the unifying container, EMP inherits a data structure that has already been validated for coordinated storage and manipulation of multi-assay experiments, including TCGA cancer resources [28] and curated single-cell multimodal landmark datasets [29], so that operations such as subsetting by sample, joining across modalities and propagating metadata are inherited rather than reinvented. EMP explicitly describes the workflow as 'natural language-style' [3], so the natural-language syntax of the module decomposition is characterised in the source description; whether the module decomposition additionally corresponds to a biology-oriented workflow syntax, or specifically embeds microbiome-targeted quality control, taxonomic aggregation and pathway mapping, is not detailed in [3], and the discussion is therefore restricted to what the source documents.

Several features differentiate EMP from neighbouring microbiome pipelines. Microbiome-centred tools such as gNOMO and gNOMO2 target community-level meta-omics integration through Snakemake and Nextflow workflows, respectively, and have been benchmarked on dedicated metagenomic, metatranscriptomic and metaproteomic datasets [27, 32]; PALM aligns multi-omics time-series data and applies dynamic Bayesian networks for longitudinal inference, including host–microbiome contexts [41]; and timeOmics extends a Bioconductor-style framework to longitudinal integration across microbiome and host layers [9]. EMP's documented scope is to couple microbiome profiling with host-side omics within a single MultiAssayExperiment container, a goal that gNOMO also pursues through a Snakemake workflow manager tailored for non-model organisms [3, 32] and that gNOMO2 extends through a modular Nextflow pipeline [27]. gNOMO2's own description indicates that its differential-abundance, integration and visualisation modules are benchmarked on four datasets [27], so the standard applied here — illustration rather than head-to-head comparison — is field-wide rather than tool-specific.

The principal design choices of EMP are best appreciated by comparing them with the broader landscape. Generic factor-analytic frameworks such as MOFA [4] and MOFA+ [5] are inferential engines that operate on matrices or tensors and infer shared and modality-specific latent factors; mixOmics provides multivariate PLS-based machinery for dimension reduction, feature selection and integrative analysis [36], with DIABLO implementing a multi-block discriminant extension [39]. Network-based approaches such as Similarity Network Fusion construct per-data-type patient similarity networks and fuse them into a single integrated network for subtyping and survival prediction [37]; Bayesian alternatives such as NetMIM handle block missingness via data augmentation [12]. Whether MOFA's factor inference generalises to the highly skewed, zero-inflated distributions typical of microbiome relative-abundance matrices, and whether the assumptions of similarity-network fusion and factor analysis can be empirically distinguished under microbiome conditions, are, to our knowledge, untested in the cited literature. EMP's reported positioning is to host analytical components within a microbiome-aware R workflow rather than to compete on factor or network methodology per se [3].

The limitations need to be stated candidly. The published evidence base for EMP is concentrated on human and mouse gut microbiome cohorts, and its documented advantages are demonstrated primarily through illustrative applications rather than head-to-head statistical benchmarking against MOFA, mixOmics-DIABLO, SNF, MLMF [7], or graph-neural-network alternatives such as DeepMoIC [14] and MO-GCAN [16] [3]. The same caveat applies across the surveyed landscape: MLMF is benchmarked on twelve multi-omics datasets [7], MOADLN on TCGA cancer cohorts [15], DeepMoIC on pan-cancer data [14], and gNOMO2 on four datasets [27]. Within EMP specifically, the available description does not enumerate uncertainty quantification, model selection or statistical inference procedures, nor does it document a re-execution benchmark on heterogeneous infrastructure; these are gaps the source itself does not close [3], so the reproducibility standard this review demands of other tools applies with equal force to EMP. EMP does not target single-cell or spatial multi-omics, which single-cell analyst [22], the multi-omics prediction and integration benchmark [34], CelLink [60] and the scRNA/scATAC integration benchmark [35] explicitly address; these are scope boundaries rather than competitive gaps. Likewise, EMP is not presented as a deep-learning platform with cloud execution, in contrast to dedicated platforms such as MOPAW on the Cancer Genomics Cloud [47] or to web-based ecosystems such as the Analyst suite [23], Profiler [21], ExpOmics [24], PhenoMultiOmics [49], NOODAI [50] and CFViSA [25]; EMP is also not positioned within automated pipeline-construction or workflow-provenance frameworks of the kind offered by moiraine [30] or by the Nextflow Research Object Crate exemplar [26].

The MOFA family deserves a specific note. The original MOFA [4] and MOFA+ [5] are the formulations whose evidence base this review considers; MOFA2, the actively maintained successor with a distinct implementation and broader adoption, is not represented in the cited cards and is therefore out of scope here. Whether claims derived from the original MOFA formulation transfer to its successor and to microbiome settings is an open question that the available evidence does not resolve.

In practical terms, EMP's documented strengths — its use of MultiAssayExperiment as the unifying container, the explicit five-module decomposition, and the host–microbiome focus — give it a specific niche among microbiome workflows, while the evidence base for these claims remains concentrated on human and mouse gut datasets [3]. What the evidence does not yet show is that EMP's analytical components outperform competing factorisation, network or deep-learning methods under controlled benchmarking, that they generalise beyond gut microbial communities, or that they scale to the regime of modern single-cell and spatial multi-omics. Treating EMP as a microbiome-specialised workflow layer that interoperates with — rather than supplants — these specialised methods is consistent with the current evidence base.

## 10. Critical perspectives, controversies, recommendations and roadmap

The maturation of multi-omics integration software has revealed a striking inversion of priorities: the field's centre of gravity has migrated from statistical novelty toward infrastructure, with workflow systems, containerised data classes and FAIR-compliant packaging now differentiating mature tools from algorithmic prototypes. Methods such as deep semi-supervised matrix factorization [40], multi-layer factorization for cancer subtyping with partial-cohort support [7] and self-attentional dynamic learners [59] continue to push classification and clustering accuracy on benchmark cancer cohorts, yet the practical bottleneck for most laboratories is no longer "which algorithm?" but "which reproducible containerised pipeline can ingest my heterogeneous tables, traverse a versioned schema, and emit a notebook that a colleague can re-run?" This shift reframes four persistent controversies that cut across general-purpose, microbiome-centred, network-based and deep-learning approaches alike, and which we argue apply with equal force to all reviewed tools rather than to any one of them.

The first controversy is reproducibility. Reviews of extracellular-vesicle biomarker discovery document how pre-analytic variability, non-standardised isolation protocols and platform heterogeneity erode cross-study concordance even before any integration step is attempted [44], and microbiome perspectives warn that, absent community standards, integrative findings risk being non-reproducible artefacts of batch structure [1]. Packages that wrap integration inside reproducible scaffolding — MultiAssayExperiment as a shared data substrate [28], moiraine as a pipeline orchestrator [30], the FAIR Digital Object Nextflow exemplar [26], and EasyMultiProfiler as an R/Bioconductor workflow built on SummarizedExperiment and MultiAssayExperiment with extraction, preparation, support, analysis and visualisation modules [3] — directly address this gap. Reproducibility in the strict sense still requires shared container specifications, pinned dependencies and execution provenance that few methods report by default, and the absence of independent re-execution benchmarks applies across the cited literature rather than to any individual tool.

The second controversy is annotation dependence. Microbiome integration is uniquely vulnerable because taxonomic and functional calls inherit the bias of reference databases, and strain-level resolution — increasingly recognised as essential for phenotype prediction in conditions such as type 2 diabetes [31] — is rarely propagated through meta-omic integration tools. Even the more mature microbiome pipelines benchmarked across 16S, metagenomics, metatranscriptomics and metaproteomics [27], as well as broader community toolkits such as bioBakery 3 for metagenomic profiling [61], rely on upstream annotation choices that constrain downstream factor interpretation. General-purpose methods, by contrast, are typically evaluated on richly annotated TCGA cancer data where gene symbols are stable; transferring them to non-model microbiomes, host–microbe systems or livestock rumen and intestinal communities [42] is largely untested and should be treated as an open methodological question rather than an off-the-shelf deployment.

The third axis is interpretability. The trustworthiness framework embodied by TMODINET [59] and the explicit network-interpretation package netOmics [10] both argue that high accuracy without mechanistic legibility has limited translational value. Yet most published deep multi-omics models [14, 15, 16, 17, 38, 40, 53] are evaluated almost exclusively by classification metrics, with feature attribution discussed qualitatively. This evidence gap means we do not know whether their latent factors correspond to biological modules or to batch-correlated artefacts, particularly under the missingness patterns endemic to longitudinal microbiome cohorts where only one of several planned assays may succeed per timepoint [9, 41]. The single-cell community has made more progress here through probabilistic latent-variable models such as scVI [18], scANVI [19] and totalVI [20], whose uncertainty quantification and harmonisation features point toward an interpretability standard that bulk-omics integration has not yet matched.

A fourth, often under-appreciated controversy is transferability across organisms and experimental designs. Tools demonstrated on human glioblastoma [48], lung cancer [52], IPF and macrophage cell-line models [8], or non-model insect hosts [32] are routinely re-applied, with minimal adaptation, to environmental communities, where the underlying assumptions about feature correspondence and library sizes may not hold. Pathway-based integration [11] and isoform-aware integration [56] further illustrate that the very notion of a "shared feature space" is task-specific, so a method's strong performance on TCGA does not license claims about its applicability elsewhere.

A candid critical assessment is therefore warranted. The benchmarking literature — including the 14 prediction and 18 integration algorithms compared across 47 single-cell datasets [34] and the 12 integration methods benchmarked on joint scRNA-seq and scATAC-seq tasks [35] — consistently shows that top-ranked methods are sensitive to dataset, normalisation and missingness regime, and that no single algorithm dominates. This implies that headline accuracy gains reported by individual methods [7, 14, 15, 16, 17, 38, 40, 53, 55, 62] are best read as within-cohort evidence rather than general superiority. The absence of head-to-head, multi-domain comparisons is a field-wide gap rather than a deficiency specific to any tool reviewed here. EasyMultiProfiler [3], for instance, has been demonstrated only on host–microbe gut microbiome systems, and its quantitative integration modules have not, to our knowledge, been benchmarked against MOFA, mixOmics-DIABLO, SNF, MLMF or graph-neural-network alternatives on shared cohorts; extrapolating its reported performance beyond those primary study systems should therefore be done with appropriate caution.

These observations translate into concrete guidance. We recommend a layered adoption strategy: anchor analysis on a versioned data class such as MultiAssayExperiment [28] first, optionally mediated by microbiome-focused workflows such as EasyMultiProfiler [3] or gNOMO2 [27] where the study system demands it; select an integration method second, matching the method's assumptions to the biological question (matrix factorisation for latent factor discovery, similarity-network fusion for patient stratification, graph neural networks for knowledge-graph-constrained prediction, longitudinal methods [9, 41] for time-series designs, and simulation-based tools [33] for pipeline prototyping and validation); and adopt a point-and-click platform last, only when accessibility demands outweigh the loss of methodological transparency. Equally, we call for an open microbiome multi-omics benchmark consortium, with shared cohorts, explicit missingness, batch and strain-level stress tests, and pre-registered evaluation criteria — a coordinated effort that, alongside FAIR packaging standards [26], would convert the field's accumulated algorithmic diversity into cumulative, comparable scientific knowledge.
