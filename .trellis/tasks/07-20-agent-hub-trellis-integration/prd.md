# Agent Hub Trellis 受控任务模式

## Goal

把 Trellis 的任务规划、上下文注入、阶段门禁、质量验证和经验沉淀机制融合为 Agent Hub 的可选原生能力，使编程、系统建设和复杂研究任务可以跨会话持续推进、可审查、可恢复并有明确验收依据，同时不增加普通问答和简单办公任务的操作负担。

## Background

- Agent Hub 已有会话、项目文件夹、工作流、Fusion 并行子任务、SSE 进度、运行日志和质量相关入口。
- Agent Hub 会话由 `ali/sessions.py` 以原子 JSON 文档保存，当前没有正式任务阶段、规划工件路径或验收状态字段。
- 工作流由 `ali/workflows.py` 构建并记录运行结果；核心调度和流式事件位于 `ali/streaming.py`。
- Trellis 使用 `.trellis/tasks/<task>/` 保存 `task.json`、`prd.md`、`design.md`、`implement.md` 和上下文清单，以文件作为长期事实来源。
- 用户已确认首版只面向编程、系统建设和复杂研究任务；普通聊天、简单问答和常规办公任务保持现状。

## Requirements

### R1. 可选受控任务模式

- 系统能够识别可能需要 Trellis 的复杂任务，并提供进入“受控任务模式”的入口。
- 普通聊天、C0 简单任务和不需要长期治理的办公任务不得被强制创建 Trellis 任务。
- 用户能够查看当前会话是否绑定受控任务，以及退出或解除绑定。

### R2. 会话与任务绑定

- 一个主会话最多绑定一个当前 Trellis 任务，并保存稳定的任务 ID 和任务目录引用。
- 任务阶段至少包括：规划中、待批准、执行中、质量检查、已完成和阻塞。
- 重新启动 Agent Hub 或切换会话后，绑定和阶段能够恢复。
- Fusion 子任务应映射为父任务下可独立验收的子任务，不把临时隐藏会话误当作正式任务。

### R3. 规划工件与审批门禁

- 受控任务能够创建和读取 PRD；复杂任务还能够管理设计和实施计划。
- 规划工件应在 Agent Hub 内可查看，并允许安全编辑或打开源文件。
- 未经用户批准，任务不得从规划阶段自动进入实现阶段。
- 用户批准后应记录批准时间、批准人/本地身份和所批准工件版本或摘要。

### R4. 调度前上下文注入

- Agent Hub 在调用模型、Claw、Agent 或 Fusion 子任务之前，应根据任务阶段注入必要的 PRD、设计、实施计划、项目规范和验收条件。
- 注入内容应有长度预算、来源标识和确定性顺序，不能无限扩大模型上下文。
- API Key、密码、Token、私有配置和未授权文件不得进入注入内容或运行日志。
- 无任务、任务文件缺失或 Trellis 不可用时，现有聊天与工作流路径应继续运行。

### R5. 阶段执行与质量门禁

- 执行阶段应显示当前步骤、完成项、阻塞项和下一步。
- 进入完成状态前必须运行任务定义的验证项，并保存命令、结果摘要和时间。
- 验证失败时任务应保持在执行或质量检查状态，不得误报完成。
- 危险命令、发布、推送、删除或外部写操作继续遵循 Agent Hub 现有授权策略，Trellis 不得绕过审批。

### R6. 原生界面与多语言

- 会话顶部提供紧凑的任务阶段与总体进度，不遮挡聊天主流程。
- 控制中心或任务详情视图展示任务蓝图、规划工件、子任务、验证结果和任务日志。
- 所有新增用户可见文案支持中文、英文和现有自动语言机制。
- 页面刷新和阶段更新不得造成主聊天区域跳动或丢失当前滚动位置。

### R7. 完成沉淀与可恢复性

- 完成任务时生成包含需求、主要修改、验证结果、遗留风险和提交信息的总结。
- 可复用经验只能在明确选择或规则允许时写回 `.trellis/spec/`。
- 任务失败、Agent Hub 崩溃或服务重启后，可从最近持久化阶段恢复，不重复执行已确认的外部副作用。

### R8. 兼容与迁移

- 未绑定 Trellis 的旧会话无需迁移，读取行为保持兼容。
- Trellis 集成关闭或目标工作区不可用时，Agent Hub 的原有会话、工作流、Claw 和 Fusion 功能保持可用。
- 首版不要求把全部历史会话批量转换为 Trellis 任务。

## Acceptance Criteria

- [ ] AC1：普通 C0/聊天任务可完整运行且不会创建 `.trellis` 任务文件。
- [ ] AC2：符合范围的复杂任务会获得受控模式建议，并可由用户明确进入或跳过。
- [ ] AC3：进入受控模式后，会话与任务绑定在服务重启和页面刷新后仍可恢复。
- [ ] AC4：规划阶段可生成并展示 PRD、设计和实施计划；未经批准无法启动实现。
- [ ] AC5：批准后，每次主 Agent、Claw 或 Fusion 调度均收到阶段匹配且已脱敏、受预算限制的上下文。
- [ ] AC6：Fusion 正式子任务具有独立状态与验收结果，父任务能汇总其完成情况。
- [ ] AC7：验证失败时 UI 显示失败原因，任务不会进入“已完成”。
- [ ] AC8：服务中断后恢复任务不会重复已经记录成功的发布、推送或其他外部副作用。
- [ ] AC9：新增界面在中文、英文和自动语言模式下完整显示，桌面与移动宽度无重叠或明显跳动。
- [ ] AC10：关闭 Trellis 集成后，现有会话、工作流、模型路由和 Fusion 回归测试继续通过。
- [ ] AC11：新增后端状态机、路径校验、上下文预算、审批和恢复逻辑具有自动化测试。
- [ ] AC12：所有任务文件访问均限制在获准工作区的 `.trellis` 目录内，不允许路径穿越或泄露秘密。

## Out Of Scope

- 强制所有 Agent Hub 对话使用 Trellis。
- 首版批量迁移全部历史会话。
- 取代 Git、GitHub、Codex、Hermes 或其他 Claw 自身的权限与审批系统。
- 在首版提供通用第三方 Trellis 云同步服务。

## Open Questions

- 受控任务应由系统识别后直接创建，还是先建议并由用户确认后创建？
- 没有 `.trellis` 的工作区，是允许 Agent Hub 自动初始化，还是只提示用户手动启用？
- 首版是否允许在网页中直接编辑规划 Markdown，还是仅提供只读预览和本地文件入口？
